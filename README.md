# Job Application Filler Skill（求职表单助手）

一个面向 Codex 的通用求职网申填写 Skill。它会从求职者提供的简历建立本地资料库，在用户已经打开目标岗位页面后填写并核对表单，逐次积累已确认的信息，并始终停在保存、下一步、声明确认和最终提交之前。

## 主要能力

- 从 PDF、Word 或图片简历提取初始资料，并要求用户统一检查确认。
- 在用户的“文档”目录中维护独立的 `求职资料` 文件夹。
- 支持多份简历、岗位方向与简历映射、证件照及成绩单等附件登记。
- 优先使用网站的简历解析功能，再逐项检查和纠正解析结果。
- 记录个人资料、填写偏好、网站选项映射和投递状态，让后续网申更省事。
- 按页面小节连续填写并集中校验，避免每填一个字段就重新扫描整页。
- 可选择不保存敏感信息，或将敏感信息单独保存在本地文件中。
- 包含 Edge/Chrome 浏览器扩展、文件上传以及 Clash/VPN/代理通信问题的排查流程。
- 不搜索岗位、不代替用户处理验证码/声明/签名，也不会点击最终提交。

## 安装

### 方法一：让 Codex 安装（推荐）

在 Codex 中输入下面的内容，并把地址替换为本仓库的实际地址：

```text
使用 $skill-installer 安装这个 Skill：
https://github.com/zxrssbahhh/job-application-filler-skill/tree/main/skills/job-application-filler
```

安装完成后重启 Codex。如果输入 `$job-application-filler` 时能够看到“求职表单助手”，即表示安装成功。

### 方法二：手动安装

1. 下载或克隆本仓库。
2. 将 `skills/job-application-filler` 整个文件夹复制到 Codex 的个人 Skills 目录。
3. 重启 Codex。

个人 Skills 目录通常为：

```text
Windows: %USERPROFILE%\.codex\skills\
macOS/Linux: ~/.codex/skills/
```

不同版本的 Codex 可能使用不同位置；如果目录不存在，可以直接询问 Codex 当前个人 Skills 目录的位置。

## 首次使用

1. 在浏览器中安装并启用 ChatGPT/Codex 的浏览器控制扩展。
2. 打开 Codex，新建一个任务。
3. 显式调用本 Skill，并提供简历路径：

```text
使用 $job-application-filler。

这是我的简历：C:\路径\我的简历.pdf
我使用 Microsoft Edge。请初始化我的求职资料，并填写我当前打开的岗位页面，停在最终提交之前。
```

首次运行时，Skill 会询问默认浏览器、敏感信息保存方式、岗位与城市偏好等信息，然后展示从简历提取的内容供用户检查。确认后才会开始填写表单。

## 日常使用

求职者先自行找到岗位并打开申请页面，然后在 Codex 中输入：

```text
使用 $job-application-filler 继续填写当前打开的岗位。
使用已保存的资料，缺失信息集中问我，停在最终提交之前。
```

Skill 会：

1. 检查岗位、表单字段和需要上传的附件。
2. 展示本次将使用的资料及仍缺失的信息。
3. 在需要时上传并解析简历，然后纠正网站解析错误。
4. 填写有可靠依据的字段并核验上传文件名。
5. 列出未填写项、占位项以及仍需用户完成的操作。
6. 更新本地资料和投递记录，但不点击最终提交。

填写时先确定当前小节的字段和值，再连续输入，通常在小节末统一校验。遇到联动字段、动态表单或报错会立即重新检查；不会通过后台请求或绕过网页控件来追求速度。多步表单默认把“保存/下一步”留给用户；若用户针对该网站明确授权，且当前浏览器权限策略允许，才会代点这些中间按钮，最终提交仍由用户完成。浏览器控制本身若持续延迟，Skill 会说明测得的情况，不能保证固定倍数的提速。

## 安全边界

- 本仓库只包含空白模板，不包含任何求职者的真实资料。
- 个人资料默认保存在求职者自己的电脑上，不应提交到本仓库。
- 登录、验证码、授权、声明、签名、测评和最终提交必须由用户完成。
- Skill 不会编造学校、日期、成绩、经历、薪资或其他事实；无法确定时会询问用户。
- 使用浏览器填写意味着资料会被发送给当前招聘网站。Skill 会遵守 Codex 当前的浏览器确认和权限策略。

## 浏览器或代理连接异常

如果 Codex 能正常联网，但无法控制 Edge/Chrome：

1. 确认选择的浏览器与实际安装扩展的浏览器一致。
2. 在 Codex 的“设置 → 电脑操作”中确认对应浏览器已启用。
3. 检查扩展是否获准在当前招聘网站运行。
4. 使用普通网页测试，不要只在 `about:blank`、扩展商店或浏览器设置页测试。
5. 重启浏览器和 Codex 后再试一次。
6. 若使用 Clash、VPN、TUN 或系统代理，检查本地/回环地址是否被错误代理。

Skill 不会直接套用固定的 Clash 配置，也不会擅自修改代理、防火墙或浏览器权限。它会先诊断，再说明拟修改的具体项目并征得用户同意。
